# Lessons

Each lesson is something past work taught us about working with the owner. It records what happened, what it showed and how it changes the work. These are not rules to tick off. Read a lesson when your work touches its topic, and apply the understanding to the situation in front of you.

| Lesson | Read it when |
| --- | --- |
| [Report against the goal](report-against-the-goal.md) | Writing a status update or findings, explaining something, or asking the owner to decide |
| [Decide and finish](decide-and-finish.md) | You're about to stop and ask the owner something |
| [When to stop auditing](when-to-stop-auditing.md) | A review or audit loop keeps finding something new each round |
| [Inspect visual work properly](inspect-visual-work.md) | Judging or fixing images, renders, 3D or UI |
| [Taste beats the AI reviewer](taste-beats-the-ai-reviewer.md) | Using a model to judge realism, quality or "looks right" |
| [Tests where they matter](tests-where-they-matter.md) | Deciding what tests to add |

## Adding a lesson

Add one when the owner corrects how you work, or when something fails in a way that will happen again. Write what happened, why it went wrong, and what it changes. Generalise only as far as the evidence goes. Then add one line here. This repo is public, so describe the situation without private names, paths or details.
